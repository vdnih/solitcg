# ソリティアTCG ルール仕様 v0.6.0

> このドキュメントの正は実装（`lib/`）に合わせて書かれている。エンジン仕様の権威は
> `docs/SPEC.md`、世界観・難易度設計の方針は `docs/pdr/PDR-001-inflated-tcg-worldview-and-turn-model.md`
> を参照。

## 1. ゲーム概要

* 一人用ソリティア形式のTCG。実際の対戦相手は存在しない。
* ライフ・デッキ枚数などの「相手側の数値」は仮想的な目標値として存在し、UIは対戦カードゲーム風に表現される。
* 割り込み処理は存在せず、処理は自分のターン内で完結する。
* バトル（戦闘）は未導入。カード効果のみで勝敗や盤面進行が決まる。
* デッキを削る・リソースを循環させる・コンボを構築することが主目的。
* ゲームは**1ターンで完結する**（PDR-001）。2ターン目のプレイは想定しない。

---

## 2. 勝利条件

| 条件 | 判定 | 実装状況 |
| :--- | :--- | :--- |
| 効果勝利（無条件） | `win` op が解決された瞬間 | 実装済み |
| 効果勝利（条件付き） | `win_if` op の条件が満たされた瞬間 | 実装済み |
| ライフ勝利 | 仮想ライフ（初期8000）を0以下にする | 未実装（ライフを増減する op が無い） |
| デッキ勝利 | ターン終了時、仮想デッキが0枚 | 未実装（ターン終了処理が無い） |

現時点で実際に到達できる勝利手段は `win` / `win_if` のみ。ライフ勝利・デッキ勝利は
`docs/SPEC.md` §12 の通りエンジン拡張が必要で、後続 Issue で対応する。

---

## 3. デッキ構築

* **メインデッキ**：ちょうど40枚、同名カードは最大4枚。
* **エクストラデッキ**：最大10枚、同名カードは最大1枚。
* エクストラデッキに編入できるカードタイプは、現時点では**存在しない**（§5 の型統合により該当タイプが
  廃止されたため）。ゾーンとしての枠組みは維持しており、対象タイプは将来のカード追加で導入する。
* 同名カードのカウントはメインとエクストラで別カウント。

---

## 4. ゲームの流れ

### 4.1 初期設定

1. プレイヤーはデッキをシャッフル。
2. 初期手札を5枚引く。

### 4.2 ターン構成

1. **ドロー**：1枚引く。
2. **メインフェイズ**：カードのプレイ、能力発動などを行う。
    * 場（board）には出せるカード数の上限なし。
    * フィールド全体に影響するカードは**ドメイン（domain）**として同時に1枚まで設置可。
3. **ターン終了**：ターン終了時に勝敗判定を行う（§2）。ゲームは1ターンで完結し、
   次のターンには進まない。

> 現状の実装では、ターン終了操作とそれに伴う終了時判定はまだ実装されていない。
> プレイヤーはいつでも任意の順序でカードをプレイ・発動できる（`docs/SPEC.md` §3）。

---

## 5. カードタイプ

| type | 説明 |
| :--- | :--- |
| monster | モンスター。hp 必須。atk / def は効果参照用（任意）。現在 hp は表示専用で、`modify_stat`（未実装）により変動する予定。 |
| spell | 魔法。プレイ後に墓地へ。 |
| artifact | アーティファクト。場に残る永続カード。 |
| domain | フィールド全体に影響。同時に1枚まで。 |

> 旧 `ritual` / `arcane` / `equip` / `relic` は ADR-006 により廃止した（挙動差が無く該当カードも
> 0枚だったため）。将来必要になれば、実際に挙動が異なる形で再導入を検討する。

---

## 6. カードスキーマ（概要）

```yaml
id: string          # 一意なID（スネークケース）
name: string        # カード名
type: monster | spell | artifact | domain
tags: [string]      # 任意の分類タグ
text: string        # 説明文
version: integer    # カードデータバージョン

stats:              # monster のみ（hp 必須、atk / def は任意）
  atk: integer      # 攻撃力（効果参照用。0以上）
  def: integer      # 防御力（効果参照用。0以上）
  hp:  integer      # ヒットポイント（0以上。hp <= 0 で破壊。※現在 modify_stat 未実装のため変動しない）

abilities:
  - when: on_play | on_destroy | on_discard | activated | on_spell_played
    pre: [ "条件式", ... ]   # 発動前提：状態チェックのみ
    effect:
      - { op: ..., ... }
```

詳細なカード定義仕様は `docs/CARD_YAML_SPEC.md` を参照。

---

## 7. 発動条件効果（pre と効果0）

* `pre`：フィールドや状態のチェックのみを行う。動作は禁止。
* **効果0**：`effect` の先頭に記載し、`pre` に対応したリソース消費を行う。
* 例：

```yaml
pre:
  - "count(type:'artifact', zone:'board:self') >= 2"
effect:
  - { op: destroy, filter: { type: "artifact" }, count: 2 }  # 効果0（消費）
  - { op: draw, count: 3 }
```

---

## 8. HPと破壊ルール

* `monster` のみ `hp` を持つ。
* `hp <= 0` になった瞬間、そのカードは破壊される（エンドフェイズを待たない）。
* 破壊時には `on_destroy` 能力が誘発する。
* `hp` の変動は `modify_stat` op でのみ発生する（現在未実装）。

---

## 9. フィールド構造

* **場（board）**：制限なくカードを出せる。
* **ドメイン（domain）**：場全体に影響するカード。常に1枚まで。
* **墓地（grave）**：破壊・使用済みカードが送られる。
* **エクストラ（extra）**：将来のカード追加のためのゾーン。現状は編入できるタイプが無い。
* **除外（banish）**：ADR-006 で追加を決定したゾーン。現状は未実装。

---

## 10. トリガー解決ルール

* 解決順は **FIFO**（先入れ先出し）。
* 同一タイミングで複数のトリガーが発生した場合も、発生順（エンキュー順）に自動で解決する。プレイヤーはキューの順序を操作できない（ADR-004）。
* `resolveAll()` 1回の呼び出しで最大100回のトリガー処理（無限ループガード）。
* `pre` 条件はエンキュー時ではなく**解決時点**で評価する。

---

## 11. `activated` 能力の制限

* `activated` 能力は **1ゲームに1度** のみ発動できる（エンジン強制）。ゲームが1ターンで
  完結するため、「1ターンに1度」と「1ゲームに1度」は同義になる（PDR-001）。
* 同一カードで複数の `activated` 能力を持つ場合も、1ゲーム合計1度まで。

---

## 12. 補足ルール

* 割り込み処理は存在しない。
* 手札枚数に上限はない。
* ドロー不能になっても即敗北せず、ターン終了時に判定する（ターン終了処理の実装後）。
